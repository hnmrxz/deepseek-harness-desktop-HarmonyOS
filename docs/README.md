## 文档纪律

- 代码事实 > 自动化测试事实 > 上游源码事实 > 文档描述 > 设想。
- 已实现、部分实现、能力边界、待验证分开写，禁止把"设计目标"写成"已完成"。
- 每个新增功能必须写清：用户价值、协议入口、状态归属、UI 入口、验证方式、失败降级。
- 能用纯模型验证的逻辑不得依赖真机；设备专属行为必须记录真机证据。
- 文档只维护一份权威结论，历史记录保留出处但不再作为第二套规范。
- README 只放"是什么 / 怎么装 / 怎么读"：逐轮缺陷写进 `13`，状态写进 `07`，能力对等写进 `parity-matrix.md`。
