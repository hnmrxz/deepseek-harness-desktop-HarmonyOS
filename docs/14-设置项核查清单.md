**端侧组合警示**：ondevice profile 永久禁用了 permission 与 shell 执行器链等插件。官方规则写明
「宿主没有权限组合时，选择器与设置行都不显示」——因此下表中标注⚠的项在端侧 Web UI 里
**可能根本不渲染**。这不是缺陷：走查时在「打开」列如实记「未渲染」，结论列填「端侧不适用」。

## 0.1 数据落点速查（$DSH_HOME = 端侧核心的应用沙箱主目录）

| 落点 | 内容 | 说明 |
|---|---|---|
| `$DSH_HOME/settings.yaml`（或 `.yml`/`.json`） | 全部设置命名空间，每 namespace 一节 | `dsh-settings-file` provider：文件锁 + 原子写 + **保留注释与键序**（leaf-level diff）；chokidar watch 热发布。读回比对**键值**即可，勿比对整文件字节 |
| `$DSH_HOME/.credentials.yaml` | `refs:`（环境变量名式引用，如 `DEEPSEEK_API_KEY`）+ `records:`（实际凭据，键为 `<scope>/<id>`，如 `llm-pi-ai/<providerId>`） | 凭据分层：inherited env（只读，最高）＞ `.credentials.yaml` ＞ `cwd/.env` ＞ `$DSH_HOME/.env`。wire 上 `redactSecrets`：secret 字段只回 `set: bool`，**永不回明文** |
| `$DSH_HOME/.agent-presets/` | 用户自定义 Agent 预设 | 随附预设为只读 system root，不可删；复制是创建自定义预设的唯一入口 |

1. **端侧被禁插件对应的 UI**：#1 权限行、#15/#16 终端卡——ondevice profile 禁用
   permission/shell 链后，这些卡片/行是否渲染、渲染成什么形态，源码层无法确证。
2. **`llm-deepseek` / `llm-pi-ai` 完整 schema 中哪些子字段出现在自定义表单**：
   设置编辑器布局由 namespace schema 驱态生成，表单暴露面以运行时为准。
3. **web-frontend 编译产物中可能存在的非插件式设置入口**：bundle 为 minified 产物，
   不作枚举依据；若运行时发现清单之外的设置入口，按新读数登记。
4. **#29 `agent-presets.modeSelectionEnabled` 的 Web UI 写入入口**：schema 存在，
   但未在 client 包源码中确证写入方。
5. **`permission` 可选预设集合**：由宿主 deployment 配置决定，端侧组合下无权限组合
   （官方规则：无组合时选择器与设置行都不显示）。

## 6. Phase 9 执行建议

1. **顺序**：先 A 通用（6 项，值类最快）→ C 内置插件（数字/开关）→ B 模型（凭据类）
   → D 预设 → E 归档（动作类）。每完成一项立即填表，不靠事后回忆。
2. **端侧不渲染项（⚠）**：在「打开」列记「未渲染」，结论列「端侧不适用」，**不反复重试**；
   若反而渲染了，如实记录形态（这本身是有价值的读数）。
3. **凭据项（#7/#14/#22）**：读回判据是「已配置/未配置」状态位，**不是**明文
   （线协议 `redactSecrets`，secret 只回 `set: bool`）。明文读取即判不通过（安全红线）。
4. **settings.yaml 比对**：有条件时用 `hdc file recv` 拉取沙箱内文件比对**键值**
   （provider 写时保留注释与键序，勿比对整文件字节）。拿不到文件时以 UI 读回为准。
5. **一次性 onboarding（#13/#14）**：走查后如需复验，手工把 `ui-onboarding.welcomeNoticeVersion`
   改小即可重新触发；不要靠清 App 数据（会连带清掉其他设置项的走查状态）。
6. **重启定义**：完全杀进程后冷启（不是切后台再切回）——`settings-file` 是启动加载 +
   watch 热发布，「重启后值仍在」才是持久化的真判据。
7. **证据**：每项结论附一句证据（读数/截图描述），不只写「通过」；不通过项按
   `docs/13-缺陷编年.md` 的读数格式登记。
