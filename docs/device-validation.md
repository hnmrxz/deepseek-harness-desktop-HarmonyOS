> 本文档于 2026-09-19 精简（保留全部条目编号与判据）；完整版见 git 历史。

**基本原则**：没有真机时允许把功能开发完成，但**不允许宣称设备验收完成**。`parity-matrix.md` 的状态分两条轴——`实现侧`（本机可证）与 `设备验证`（真机才可证，未验一律 `PENDING`）；任何"设备上已好"必须以实测读数为据。
矩阵 §3.3 点名统一进本文的六类（视觉像素 / 手势 / 键盘 / 触控笔 / 系统权限 / 文件选择器）仍待从矩阵"设备验证"列逐面展开；**不在此文 ≠ 已验证**。实测读数见 `device-validation-readings.md`（缺陷台账 F1–F32）与 `docs/80-修复与优化方案.md`（F1–F33）。
凡未标 ✅ 的条目，未过之前不得宣称对应能力"已与官方对齐 / 已解决"。

## 2. 被引用条目的完整判据

### D8. 轨迹时间总览的观感与手势（P2 §11；被 `ConversationPane.ets` 引用）

轨迹视图上方新增「总计 + 每格比例条 + 拖动聚焦 + 统计四项」，判断只能靠真机：

1. **比例条在手机上看得清吗**：格子多、耗时悬殊时（如 8 秒助手回合 + 十几个几十毫秒工具格）最窄的格可能只有一两个像素。判据：是否还能看出"大概有这么多格"、是否需要给最窄格一个最小宽度。**这是本项最可能需要返工的地方。**
2. **拖动聚焦与列表滚动冲突**：比例条 `PanGesture({direction: Horizontal})` 与下方列表纵向滚动、条本身点击（`onClick` 组件相对坐标换算）要能共存。判据：横拖只换聚焦格、纵滑仍滚列表、轻点能聚焦。
3. **聚焦详情是否够用**：目前给「种类 · 第 n/共 m 格 · 开始于 hh:mm · 耗时」。判据：不看列表能否凭这一行知道"这是哪一步"；不够则加强联动。
4. **双向联动的手感**：
   - 条→列表：拖动松手或点选后，列表滚到对应条目并高亮（`ScrollAlign.START` 对齐首行）。判据：跳转位置对不对、动画是否突兀。
   - 列表→条：滚动列表时条上聚焦跟着**首行**走。判据：是否让人误以为"条在自己动"；观感不好可改成只在用户主动滚动后更新，或去掉这一路（保留条→列表即可）。
   - **最需要盯的是抖动**：两路互相触发时不应来回跳。当前靠"拖条期间关掉列表那一路"+"滚到条目行首使两侧一致"避免，属**推断**，必须实机确认。
   - 条→列表当前用**立即跳转**（非平滑滚动——平滑会在动画途中反复触发滚动回调、让聚焦扫过中间每一格）；真机上若"跳得太硬"，补"程序化滚动期间挂起列表→条"后换回平滑。

### D40. 返回键层级：真机上只有"一次一层"，且每一步都看得见（P8-1；被 `docs/07` 引用）

本机只能证明决策（2304 种组合态矩阵任一组合只产生一个 `BackAction`）与 `Index.consumeBack()` 分支；"按下返回后屏幕真的变了一层"必须真机看。判据（每一步都必须是"看得见的一层"）：

1. 手机单栏：工作区 → 浏览文件（第 1 层）→ 点开一个文件（第 2 层预览）；按系统返回 ⇒ **回到文件树**（不是停在这层、也不是直接回工作区列表）；再按一次 ⇒ 回工作区列表。
2. 同一预览页，点页头那枚返回箭头 ⇒ 与系统返回键**完全同一步**（两次操作可互换，结果一致）。
3. 预览打开后按返回，**再等 10 秒**（让 Host 推新事件）⇒ 预览**不得自己回来**（假关闭回归判据：预览真值在中枢，视图只清镜像就会复现）。
4. 手机单栏：从列表点进一个会话 ⇒ 按一次返回 ⇒ **回到列表**（会话仍在、仍选中，再点进去内容还在）；**不得**"第一次按返回没反应、第二次直接退出应用"。
5. 抽屉打开时按返回 ⇒ 只收抽屉（页面不动）；抽屉 + 浮层同时开着 ⇒ 仍先收抽屉。
6. 任意浮层（凭据/设置草稿/选择/详情半模态）开着 ⇒ 按返回只关浮层；关掉后**重开同一个浮层**，不得带上一次的内容、回执或"写入中"状态（归一化判据）。
7. 多栏（平板/2in1）三栏下，把右栏切到「预览」面板并选中一个文件 ⇒ 按返回：**记录实际发生的事**（本端按"并排栏不算层"处理 ⇒ 先退出文件浏览/或交给系统）。**这条是待确认项**（`docs/07` 已登记）：若实测观感是"预览明明在屏幕上，返回却不关它"，要把"该面板此刻是否显示"也纳入 `previewIsLayer()` 的判据。
8. 三栏/双栏：窗口从宽拖到窄（越过断点）后按返回 ⇒ 不出现"按了没反应"（层级在窄档下仍成立）。

### D46. 操作区在窄屏/大字号下不得被裁掉（P8-4b；被 `check-feature-wiring.mjs` 引用）

本机只能证明**结构**（三处仍是可换行的 `Flex`，由接线门禁的"必含模式"规则钉住）与编译通过；换行发生在渲染期（真实字体度量、系统字号、软键盘可用高度、ArkUI 对 `Flex({wrap})` 的实现），**纯设备判据**。判据（手机 360×800 为基准，再各来一次"系统字号最大"）：

1. **输入区工具行**：`@ 引用` `/ 命令` 附件 图片 计划 权限 **模型**——七件控件一个都不能少；放不下时**换到第二行**，**不允许**任何一件被挤出右边缘（重点看最右边的「模型」）。
2. 点「模型」chip 能打开模型选择浮层（被裁掉的按钮点不到，这条同时验证可达性）。
3. **会话头视图切换行**：切到「轨迹」视图 ⇒ 右侧「展开全部 / 收起全部 / N 条事件」三件都在；窄屏下允许换行，不允许消失。
