# 界面重塑：面向端侧核心（D7，历史文档·结论摘要）

> 本文档于 2026-09-19 由完整版精简为结论摘要；完整过程见 git 历史（本文件压缩前版本）。

这是一份**已执行**的规划文档。改造清单主体已落地：一级导航收敛（工作区 / 设置，删掉「待决」「会话」页签）、信息架构从「连接中心」改为「会话 + 核心」、远程接入降级为可选。**现行事实以 `50-端侧核心运行架构.md` 为准**；本文件只保留「为什么当初这么设计」的推理与未被覆盖的纪律。

## 1. 为什么要重塑（结论）

D3 是在「远程客户端」定位下写的：把「连接一个 Host」当前提，于是添加 Host/配对/隧道/连接诊断占一等位置，而「本机核心」在界面里根本不存在（版本、安装位置、首次启动耗时、回滚、原生件加载失败、插件可装性等问题在旧架构下无处安放）。结论：不是加一个页面，而是把一级信息架构从「连接中心」改成「会话 + 核心」双中心，远程接入降级为可选能力。

## 2. 仍然有效的设计决策与理由

- 「核心」与「设置」相邻但不合并：核心是「能力与运行」，设置是「偏好与凭据」；把核心状态塞进设置会造成「设置页里藏了一个正在运行的服务器」。
- 不可用的动作必须把**原因显示在按钮下方**（`CoreActionSpec.reason`）；禁止静默禁用、禁止点了没反应。
- **未探测 ≠ 未知**：未探测的事实写「未探测」并给出探测条件（`unknownFact(label, howToProbe)`），不编值。
- 「尚未接线」必须只用于真没实现的东西：`start/stop/restart/rollback/install` 是真实实现（未接载体时返回**运行时探测的真实原因**，载体接上同一段代码直接可用）；只有 `import`（需文件选择器+容器校验+签名检查）与 `diagnose`（需运行时事实）真的没做。
- `rollback` 走 `CoreStore.rollback()` 且**不做健康检查**——回滚的语义就是退回已知可用的上一版。
- 插件三态分类 `PluginNative{PURE_JS, NATIVE, UNKNOWN}`：**UNKNOWN 不视为可安装**（把「不知道」当「纯 JS」会把未知渲染成可安装）。端侧自足后清单由打包时沿依赖闭包判定写进树内，本地正常不出现 UNKNOWN；三态保留是因为连远程 Host 的路径仍只能得到 UNKNOWN。
- 插件清单**只排序不隐藏**（按「依赖原生 → 默认禁用 → 其余」排 152 行）：清单的价值在于「到底装了什么」能查全。旧核心包不带清单时如实说「该包没带清单」，不说成「插件为零」。
- 端侧插件清单来自树内 JSON（打包时算好，只读一份、不遍历 27000 余文件）。
- 会话空态按核心阶段五档分档（`Core.sessionEmptyCopy(phase)`：未接线/未安装/解包中/启动中/失败）——新架构下「没连上」最常见原因是本机核心还没起来，不是地址填错；空态由 `WorkspaceBrowser`/`WorkspacePane` 的 `emptyTitle`/`emptyHint` 承载（`SessionListPane` 自 E108 起无渲染点，P1-1 已删除）。
- 设置页的「远程 Host」视图与「核心」页的端侧插件清单**不是同一份数据，不要合并**。
- 诊断按 `DiagMode` 分流：本地核心模式隐藏 TLS 与认证两项（回环 + `--skip-auth` 下不适用）；远程模式才显示远程专属判定。
- `ConnectPane` 从主流程降级为「设置 → 设备 → 远程 Host（可选）」；hostkit 配对/隧道/二维码归入高级并标注「连接远程 Host 的可选能力」。
- 热更新下载的 `.so` 会被系统拦截，含原生 `.node` 的插件必须随应用发版——这是插件分类呈现的硬约束。
- 长任务要可见：首次解包（约 2.5 万文件 / 约 63 MB 压缩包）必须给进度与预计时间，不是转圈。
- 启动参数（`dshLaunch*`）保留但改语义：默认由本地核心自动注入，显式参数仅用于调试/远程。
