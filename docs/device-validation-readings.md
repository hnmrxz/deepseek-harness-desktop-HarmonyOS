## §2 缺陷台账

### F1（P0）`write` / `edit` 在真机上**永远失败** ⇒ Agent 不能创建或修改任何文件

- 读数（`tool/result` 原文）：
  `Error: cannot write "/data/storage/el2/base/haps/entry/files/workspace/.dsh-write-probe.md": EACCES: permission denied, link '…/..dsh-write-probe.md.36035.c94a5770….tmpdir/.dsh-write-probe.md.tmp' -> '…/.dsh-write-probe.md'`
- 同一轮里 `write` 连试 3 次全部同因失败（第 4 次才转成"申请越权"）。
- 上游机理（已读源码，`@deepseek-ai/dsh-fs-local/lib/index.js:494 writeFileAtomic`）：同目录建
  `.${basename}.${pid}.${uuid}.tmpdir/` → 写 `${basename}.tmp` → **新建**时 `link()`（no-replace）、覆盖时 `rename()`。
  报错落在 `link()` 且两端同目录 ⇒ **不是 EXDEV，是沙箱策略拒绝 `linkat`**。
- 影响面：回合产出文件行（D39）、交付物分享（D54）、正文路径可点（D50）、文件预览（D16 §7）、
  目录自动刷新（D30 §3）——**DSH 的核心价值（改代码）在设备上不可用**。
- **✅ 已修并复验（2026-09-17）**：在 `hostcore/app/main.js` 的引导段装了一个 **`link` 降级垫片**
  （运行期组合，不改上游、不改核心树）：`node:fs/promises` 的 `link` 与 `node:fs` 的 `linkSync`
  在 `EACCES/EPERM/ENOSYS/EOPNOTSUPP/ENOTSUP` 时退回 **`copyFile(tmp, dst, COPYFILE_EXCL)`**——
  保住"不覆盖已存在文件"，丢掉原子性（**已在旁路日志如实打一行，并登记为端侧已知取舍**）。
  用 `Object.defineProperty` 而不是赋值：`node:fs` 的导出是 **getter-only**，赋值会静默失败
  （那会变成"装了垫片但没生效"）。
  **真机复验**：
  - 启动读数：`link 降级垫片已安装（沙箱拒绝 link 时退回 copyFile EXCL）`；
  - 让 agent 写文件 ⇒ `tool/result` 原文 `<path>…/f1-probe.md</path><content>Created file</content>`，
    回读 `1: hello-f1 (End of file - total 1 lines)` ⇒ **写成功了**；
  - 降级垫片确实命中，且把 errno 原文留了下来：
    `link() 被沙箱拒绝，已降级为 copyFile(COPYFILE_EXCL)：… /f1-probe.md.tmp -> …/f1-probe.md（code=EACCES errno=-13 syscall=link）`。
  ⇒ **根因确证：鸿蒙应用沙箱对 `linkat` 返回 `EACCES(-13)`**（不是 EXDEV），修法对症。

## §3.6 超长正文折叠成一行（用户要求，2026-09-17 落地并真机复验）

**需求原话**：「对话里超长的应当和官方 web 一样只显示一行，点击再展开全部内容。」

**先做的一步（重要）**：在官方客户端 bundle 里找过这个行为——`dsh-client-ui-conversation`
与 `dsh-client-ui-chat` 里**没有**消息正文的 `line-clamp`（找到的 `clamp` 都是 CSS 宽度
`clamp()` 与富文本编辑器的选区 clamp）。所以这条**不是照抄官方**，而是按用户口径实现的；
`docs/20` 里原本也只有「思考块默认折叠为一行」这一条，正文没有折叠规则。

**范围（与用户确认过）**：只折叠**超长**的，短消息原样——把每条都折成一行会让整段对话没法读。

**实现**（`entry/src/main/ets/view/MessageRow.ets`）：
- 判据放在**纯文本**上（`plainTextOf(parseMarkdown(body))`），不是 Markdown 源文——
  用源文会把标记算进字数，把不该折的折了；
- 阈值：纯文本 **> 500 字** 或 **> 6 行**（两个条件都要："500 字一行写不完"与
  "6 行短句加起来不到 500 字"都很常见，只用一个会漏）；
- 折叠态渲染**单行纯文本 + 省略号 + 「展开」**；展开后仍是原来那套 `MarkdownRenderer`，
  并在长文时给一个「收起」；
- **流式进行中不折**（正文还在长，折了会看到"越写越短"）。

**真机复验**：助手那条 `I could not create the file. f7-…` 显示为**一行 + 省略号 + 「展开」**；
点「展开」后恢复完整 Markdown。（截图：`dist/lab/01-collapse.jpeg`）

**复验时踩到的一个读数陷阱（记下来）**：`uitest dumpLayout` 报的是节点的**完整 `text` 属性**，
不是"视觉上渲染出来的那一段"——所以折叠之后 dump 里照样能看到整段正文，
**不能靠 dump 判断折叠是否生效**，要看有没有「展开」这个节点 + 截图。

**顺带看到的两个布局点**：
- 只有思考块、没有正文的助手消息，会渲染成「只有一行动作条」——本轮之前就是这样（空正文分支），
  不是这次改动引入的；但它看起来像"消息丢了"，建议给这类条目一句占位说明。
- 输入框里插入的**会话提及**是 `@[标题](dsh-session:<base64>)`，很长且会在窄输入框里折 4~5 行
  （见截图里的 `@notes/ @[Fetch example.com page title](dsh-session:InNlc3Np…)`）。
  官方 web 会把它渲染成一个 chip；建议输入框内在**失焦时**把这类 mention 折叠成 chip。

### §3.11.2 目标栏时有时无的真正线索：**两个来源互相覆盖**

> 原则沿用本仓不变式：**不改上游源码、不改核心树**，端侧差异只走运行期组合。

### 6.1 F9：把入口脚本的放置接进构建（**先修这条**）

不修则后面所有修复都可能"构建绿、设备上没生效"。

1. **自动放置**：在 `entry` 的 hvigor 构建前置里跑 `tools/place-host-app.mjs`；
2. **门禁**：新增 `tools/check-host-app-fresh.mjs` —— 逐字节比对 `hostcore/app/{main.js,fetch-shim.js,undici-shim.mjs,undici-loader.mjs}`
   与 `entry/src/main/resources/resfile/resources/app/` 下的副本，不一致就 **exit 1**；挂进既有门禁清单，
   并在已知坏版本上红一次（归真验证）。

**验收**：改一行 `hostcore/app/main.js`（加临时标记）⇒ 直接 `devecocli build` ⇒ 解包 HAP 能看到那一行；未重放时门禁必须红。

### 6.2 F7：审批结果是**字符串**，不是对象（一行修复）

- 落点：`appstate/src/main/ets/store/SessionHub.ets` 的 `answerWaterfall()` ——
  改成直接 `sendEventResult(pendingId, {kind:'result', value: outcomeValue})`。
- **不要一起改坏提问那条路**（它的 `{answers:[…]}` 形状是对的）。
- 补 fixture：钉住"审批结果帧的 `value` 是**字符串**"+"提问结果帧的 `value` 是 `{answers:[…]}`"。
- **验收（真机）**：触发一次越权 ⇒ 点「允许一次」⇒ 事件里出现 `approval/decided {"outcome":"allowed-once"}`，
  且工具继续执行。

### 6.3 F1：`link()` 降级垫片（运行期组合）

- 在 `hostcore/app/main.js` 引导段安装 **`link` 降级垫片**：`node:fs` / `node:fs/promises` 的 `link`（含 `linkSync`）
  在 `EACCES/EPERM/ENOSYS/EOPNOTSUPP` 时退回 **`copyFile(tmp, dst, COPYFILE_EXCL)`**：
  - 保住"不覆盖已存在文件"（`COPYFILE_EXCL` ≈ `link` 的 no-replace）；
  - 丢掉**原子性**与"同 inode" ⇒ **必须在旁路日志如实打一行降级说明**（一次性，不刷屏），
    并在 `docs/parity-matrix.md` 登记为端侧已知取舍。
- **先做设备探针**：垫片第一次命中时把 `code`/`errno`/`syscall` 原样打进日志（不能只看代码猜 errno）。
- 替代方案：若 `copyFile` 也受限，退回"`open(dst,'wx')` + 写 + `fsync`"（同样保 no-replace、同样丢原子性）。
- **验收（真机）**：`write` 工作区内新文件成功；`edit` 同文件成功；日志有降级说明；
  对**已存在**文件走 `createIfAbsent` 时仍拒绝（no-replace 没被削弱）。

### 6.4 F12 / F18：待决卡必须**占位**，动作行必须可达

- 落点 A（会话页接管）：把接管卡放进**自己的纵向流**（或 `Scroll` + **底部固定动作栏**），
  键盘弹起时动作栏仍在可视区；接管期间输入区**让位**（官方语义就是 composer takeover）。
- 落点 B（工作区页）：`WorkspaceBrowser.ets:204-225` 的 `.constraintSize({maxHeight:320})` **补 Scroll**
  （或改成"可用高度的百分比"），动作行 sticky。
- **验收（真机）**：三选项提问卡 ⇒ 三项都能选、自定义输入能输入、**三颗键都点得到**；
  手机竖屏 + 键盘弹起两种状态、工作区页与会话页两个挂载点都成立。

### 6.5 F22：正文渲染必须过 `userFacingBodyOf()`（**安全出口，最优先之一**）

- 落点：`MessageRow.ets:169`、`ReasoningRow.ets:70`；并核 `TurnView.ets:474`、`ConversationPane.ets:584/620`。
- 改法：正文一律 `userFacingBodyOf(item)`；值为空且 `internal === true` 时渲染既有文案
  「内部事件正文不显示（共 N 字符）…」（`TrajectoryDetail.ets:59` 已有，**复用不要新造**）。
- **门禁改法（关键）**：现在的接线门禁只查"有没有调用点"，所以漏了渲染这一路。
  改成负面规则：这几个文件里**不允许把 `item.body` 直接喂给渲染器/可访问性文本**。
- **验收（真机）**：跑一轮带系统提示词的会话 ⇒ 轨迹视图「系统」条**只有**那句"内部事件正文不显示（共 N 字符）」；
  对话/复制/引用/朗读四处都读不到；**反向**：普通助手正文四处照旧可读。

### 6.6 F19：冷启重连的竞态（**先修这条才能让后续取证可信**）

- 落点：`entry/.../pages/Index.ets` 的"等待记住的 Host"那段与 `HDSH-AUTO 已接入本端 Host` 的触发时序。
- 改法：① 收到**新 token/新地址**时**无条件**重新发起连接；② 首次失败后**退避重试**（1s/2s/5s…），
  而不是 45 秒后彻底放弃；③ `等待结束 state=… attempts=N` 改成**有终态**的日志。
- **验收（真机）**：连续冷启 **10 次**，每次都出现 `connect 结果：ok=true`；不得有停留在「离线中」的实例。

### 6.7 F24：命令必须真的能执行

- ① `Composer.ets:633-637`（斜杠菜单）与 `/ 命令` chip 走与 `CommandList.onRun` **同一套**分流；
- ② `Index.sendDraft()` 识别"整条草稿就是一条命令"并改走 `commands/execute`；
- ③ 给「命令面板」补一个**触屏可达入口**（它里面还住着"本会话模型"与"目标栏"）。
- **验收**：`docs/device-validation.md` D32 §1–§6 与 D51 §1–§7。

### 6.8 F25 / F26 / F27：把 `sharp` 的原因查出来并让诊断可用

1. **F27 先修**（否则查不下去）：`nativeFact()` 把 `missing` 的**原因**写进被渲染的 `value`（只带前 ~60 字），
   或给核心页一个能展开 note 的落点。
2. **F26**：把「导出诊断」接上（它本来就是这类信息最自然的出口）。
3. **F25**：拿到原因后再决定是修调度器（soname/RPATH 软链、`LD_LIBRARY_PATH`）还是如实降级
   （"这台设备上不能发图"远好过"发了但被静默拒绝"）。

### 6.9 F28：消息反馈的四个形状问题（一次修完，别只修一半）

1. **回包双层包装**：`list` / `put` / `delete` 的回复都是 `{ok:true, value:{…}}`。
   两处都要改：`feedbackFromReply()` 读 `value.value.items`（并**同时兼容**单层，别把老形状打死）；
   以及**判成功要看内层 `ok`**——只看外层会把 `version-conflict` 当成保存成功（假成功）。
2. **新建必须 `ifVersion: null`**：ArkTS 的 `Record<string, Object>` 表达不了 null，
   要么给 `argsFor` 之外留一个"显式 null"的编码口子，要么把新建改走 `ifVersion` 缺省即 null 的语义——
   **必须先向上游确认**（用 fport 实测：不带 ⇒ `version-conflict`）。在这之前，"保存新评价"这条能力应当如实标注为不可用。
3. **提交取向取错了源**：`MessageRow.ets:198` 用的是 `storedRating`（已存行的 rating），
   应当用**用户这次点的取向**（`openFeedback` 时那个 `rating`，`TurnView`/`ConversationPane` 里已有 `fbRating`）。
   这是"提交永远发不出去"的**直接原因**，与第 1 条各自独立。
4. **失败要有回执**：`feedback.incomplete` 现在被 `feedbackNoticeTextOf` 吃掉（面板上不显示）。
   任何"提交没成功"都必须贴着面板说一句。
- **验收（真机）**：给一条助手消息点「有帮助」→ 选类别 → 填说明 → 提交 ⇒ 面板关闭、操作条评价态高亮；
  Host 侧 `messageFeedback/list` 能读到该条；再打开面板 ⇒ 类别与说明**已预填**；取消再开 ⇒ 仍是已存内容。

### 6.10 F29：返回后重进同一条会话 ⇒ 0 条条目

- 现象见 §2 的 F29（轨迹「0 条事件」+ 对话整屏空白；切别的会话再回来可恢复）。
- 定位建议（按嫌疑排序）：① `Scroller.scrollToIndex` 在**数据未到**时被调用，把列表状态打坏（D53 的恢复路径）；
  ② 会话切换时 `follow`/`page` 的**代际**没有对齐，回来的那一份快照被当成"旧的"丢弃；
  ③ 列表的 `LazyForEach` 数据源在重建时被清空而没有重新灌入。
- 判据（修好后必须成立）：进会话 → 返回 → **再进同一条** ⇒ 正文照旧；连续来回 10 次不空；
  轨迹视图的「N 条事件」两次进入一致。

### 取证纪律补充（本轮新踩到的）

- **待决卡会改变整页布局**：一条待决（或一条顶部横幅）会把下面的所有行下移 100–200px，
  于是"上次记下的坐标"必然点错。**每次点按前都要重新 dump 取 bounds**，不要复用上一轮的坐标。
- **`F1` + `F7` 会自我放大**：写操作必然失败 ⇒ 每次都触发一次越权审批 ⇒ 列表页不断堆新待决卡。
  验收时如果发现"页面被卡片占满"，先看是不是这个循环，而不是界面 bug。
