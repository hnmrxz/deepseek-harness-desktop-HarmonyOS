# 安全与 API 错误呈现审计

> 本文档于 2026-09-19 精简（保留被代码/门禁引用的锚点结论）；完整版见 git 历史。

## 1. 总结论

- 普通对话气泡层不是系统提示词的直接泄露面（`system/message` 标记为内部事件、`conversationAudienceOf()` 对 `internal` 一律返回 `HIDDEN`、会话可见集合排除 `system/message`）；但安全边界必须提升到"**任何用户可触达的产品路径都不可见**"——轨迹详情、搜索、复制/引用、导出、通知、日志逐一封堵。
- API 错误：已有错误码文案表、重试倒计时与 `lastError`；必须收敛为"错误来源 → 用户状态 → 操作入口"的一一映射，不得把连接错误、请求错误、模型重试、宿主拒绝、参数错误全部挤进一个"失败提示"。

## 2. 系统提示词防泄露

- 有效防线（必须继续保持，不因"用户看不到"而删来源标记）：`TrajectoryItem.internal` 是来源事实标记，不靠正文特征判断；fixture 覆盖系统角色隐藏、内部条目隐藏、伪装成普通回答的内部条目仍隐藏；搜索不把内部条目计入对话命中。

### 2.2 旁路封堵（要求清单）

1. 轨迹详情：内部条目一律不画正文类字段（已处理 P8-5：`TrajectoryDetail.trajectoryDetailRows()` 只留结构化事实并说明"为什么看不见"，判据取自 `Turns.mayExposeBodyToUser()`，与对话可见性同源）。
2. 复制/引用：正文一律经 `Turns.userFacingBodyOf(item)` 取，内部条目给空串（已处理 P8-5）——按 §2.3 口径**出口必须自带判据**，不能靠"上游调用点恰好没传"。
3. 搜索：任何返回可点击结果的搜索接口必须按 audience 过滤，不能只在 UI 层隐藏结果。
4. 导出/诊断：只提供结构化状态、错误码、时间线和必要诊断字段，不打包原始会话事件/系统提示词。
5. 通知：不携带系统消息正文、隐藏事件正文、工具敏感参数或完整错误堆栈。
6. 日志：hilog/trace 不打印系统提示词、token、Authorization、cookie、完整请求头或完整原始 API payload（已逐行核对未发现缺陷——是"读出来的结论"，非门禁保证）。
7. 附件/工具参数：可能含内部上下文、密钥引用、系统路径，展示必须走脱敏/摘要策略。
8. 未知事件 fail-closed：原始 JSON 不得当用户正文；未识别事件只记类型名（`unknownTypes`），不存原始 JSON。

### 2.3 安全验收标准（锚点：被 Index.ets、Turns.ets 引用）

任何包含以下特征的事件：

- `speaker = SYSTEM`
- `internal = true`
- 未知/未确认的上游事件
- 认证、凭据、cookie、token、授权头
- 工具原始参数或内部诊断 payload

均不得进入：`普通对话 / 搜索结果 / 复制 / 引用草稿 / 用户通知 / 用户导出`。允许进入开发诊断的数据必须单独定义白名单，并默认脱敏。

## 3. API 错误在会话窗口中的呈现

**3.1 基础能力**（已有，须收敛为"来源 → 状态 → 操作"映射）：`lastError` 状态、46 个上游 RemoteErrorDetailsMap 专门文案、模型重试条目与倒计时、发送失败草稿恢复、队列竞态静默收敛、连接层以 WebSocket close + 心跳决定连接死亡。

**3.2 会话窗口必须区分的六类错误/状态（禁止全写成"操作失败"）**：

| 来源 | 会话内主提示 | 是否影响会话 | 主操作 |
|---|---|---|---|
| 连接断开 | "连接已断开" | 是 | 重连 |
| 请求被 Host 拒绝 | "请求未执行" + 人话原因 | 否/取决于请求 | 修改后重试 |
| 模型 API 错误 | "模型请求失败" + 可读原因 | 当前轮失败 | 重试/换模型 |
| 自动重试中 | "正在重试 · 第 n 次 / 倒计时" | 当前轮保持运行态 | 取消/等待 |
| 输入已排队 | "已加入待发队列" | 否 | 查看/撤销 |
| 参数/附件错误 | "本次输入未发送" | 否 | 修改输入 |

（已处理 P8-6：重试链落成官方逐字状态行 `{标签}（{n}/{max}） · {s}s`（等待重试/正在重试/已重试/已取消），整条重试链只占一行、按上游 `retryId` 合并；取消后变"模型请求重试已取消"不再倒数。）

**3.3 提示位置（要求）**：当前轮 API 失败 → 紧贴该轮结束位置的错误行；连接断开 → 会话 Header/状态区持久状态 + 轻量 banner；自动重试 → 当前轮 RetryRow；输入参数错误 → Composer 附近；全局 Host 错误 → 全局状态区。错误提示不得覆盖最后一条用户消息、发送按钮或正在编辑的草稿。

### 3.4 错误生命周期（锚点：被 ErrorLifecycle.ets、check-feature-wiring.mjs、check-layout-fixtures.mjs 引用）

统一采用：`发生 → 分类 → 投影 → 用户提示 → 操作 → 成功/继续失败 → 清理`。其中"清理"必须明确：

- **新一轮成功后清除旧的 transient error**；
- 持久连接问题只有真正恢复连接后才清除；
- retrying 状态不能同时显示成 error + running；
- 同一错误不能因为多个事件重复堆叠多个 banner。

（已处理 P8-6c：零依赖 `model/ErrorLifecycle` 把错误分两种作用域——**由写那句话的地方决定，不从文案猜**：`connection` 只有真正连上才清、`action` 发送被接受/一轮成功跑完即清；中枢 `setConnectionError()` 是连接层 5 处唯一入口。重试是独立一行 RetryRow 不占错误槽位；结构上只有一个 `lastError` 槽位。）

## 4. 敏感错误信息（要求）

UI 不得直接暴露：API Key/token/cookie、Authorization 头、完整 URL 中的 token 参数、Node/JS stack trace、本机绝对路径（除非用户主动要求查看）、原始 HTTP headers/body、完整系统提示词。技术诊断保留错误码 + 受控摘要（如 `模型请求失败 · code=provider/auth-failed · 请检查凭据`）。Host 原文进界面前统一过 `Redact.scrubCredentials()`（P8-5，`FailureText.hostDetail()` 一处收口、三个调用点共用）；**仍缺**：诊断报告 `traceLines` 未过脱敏（当前核对不含凭据，但非门禁保证）。

## 5. L0 fixture 要求与 L2/L3 验证

L0：1. `system/message` 永远不进入对话、搜索、复制、引用；2. `internal=true` 即使正文伪装成普通回答也必须隐藏；3. 未知事件原始 JSON 不得成为用户正文；4. error message 中出现 token/cookie/Authorization 必须脱敏；5. 模型失败、连接失败、Host 拒绝、参数错误必须得到不同的用户状态；6. retrying 与 error 不能同时占用冲突状态槽；7. 新一轮成功后旧 transient error 必须清理；8. 排队状态不得显示成失败；9. 失败恢复草稿时不得覆盖用户新输入；10. 所有错误提示都不得遮挡 Composer 和最后可操作区域。

L2/L3 待真机验证：错误 banner 是否遮挡消息/Composer；错误出现后滚动位置是否稳定；软键盘出现时错误提示是否覆盖输入区；长错误文案是否被裁切且无法查看完整内容；后台恢复后错误状态是否重复弹出；通知是否泄露错误原文、系统消息或敏感字段。

## 6. DONE 定义

"系统提示词安全" = **对话隐藏、搜索隐藏、复制隐藏、引用隐藏、通知隐藏、导出隐藏、日志脱敏、未知事件 fail-closed**；"API 错误体验" = **错误分类正确、提示位置正确、文案可操作、不覆盖内容、不伪成功、不重复堆叠、恢复后清理**。
