## 2. 权限清单（最小化：**2 项**）

| 权限 | 等级 | 用途 | 代码证据 |
|---|---|---|---|
| `ohos.permission.INTERNET` | normal | 连本机 `127.0.0.1` 上的 Host、以及用户显式配置的远端 Host | `connection/protocol/HttpClient`（`http.request`）、`RemoteMux`（WebSocket）、`entry/runtime/NodeRuntime`（就绪探活） |
| `ohos.permission.KEEP_BACKGROUND_RUNNING` | normal | 长任务在后台继续跑（`DATA_TRANSFER` 模式），否则切后台即被冻结 | `platform/notify/KeepAlive.ets`（`backgroundTaskManager.startBackgroundRunning` / `stopBackgroundRunning`） |

> **本轮删除**：`ohos.permission.GET_NETWORK_INFO`。
> 删除依据：该权限唯一的取值入口是 `@ohos.net.connection` 一族（`getDefaultNet` / `hasDefaultNet` / `getNetCapabilities`），
> 而**全仓没有任何调用点**（`grep -rn "getDefaultNet\|hasDefaultNet\|getNetCapabilities" entry platform connection` 为空）。
> 应用自己的"离线"判据来自中枢状态（`Index.offline = (hub.phase === HubPhase.DEGRADED)`），与系统网络信息无关。
> 权限理由串 `perm_network_info_reason` 一并删除，避免留下"声明了却没人用"的痕迹。

**未申请的（也是刻意的）**：`READ_PASTEBOARD`（读剪贴板，见 `parity-matrix` 的 `hdsh-clipboard` 行：用户粘贴走系统文本域自己的菜单）、
公共存储/媒体权限（文件读写只发生在应用沙箱；选文件走系统的 `DocumentViewPicker`，由系统授予**单次**访问，实测 `FilePicker.ets` 只 import `@kit.CoreFileKit` 的 `picker`/`fileIo`，不申请任何权限）、`GET_WIFI_INFO`、位置、通讯录、相机（添加附件走系统**选择器**，由系统授予单次访问）。

## 3. 数据与网络（隐私姿态）

| 问题 | 事实（代码可核实的部分） |
|---|---|
| 有没有遥测 / 埋点 / 崩溃上报？ | **没有**。全仓没有第三方统计 SDK，也没有向外部地址发送数据的路径；诊断报告只在用户点击"复制"时进剪贴板 |
| 数据发到哪里？ | ① 本机回环 `127.0.0.1:<port>` 上的 Host（**只绑回环，绝不 `0.0.0.0`**，见 `docs/dev-host.mjs` 的红线说明）；② 用户在「连接」页**显式填写**的远端 Host |
| 收集设备标识吗？ | **不收集**。全仓没有 ODID / AAID / 序列号读取（实测 `grep -rn "ODID\|AAID\|oaid\|getUdid\|serial"` 无命中）。`platform` 只读"形态 / 输入设备 / 系统语言"这类**当下事实**用于布局与文案 —— 其中 `InputDevices` 用到的 `getDeviceInfoSync(deviceId)` 是**输入设备**的编号（键鼠枚举，无 `@permission`，且不落盘、不外发），不是用户或整机标识 |
| 会话内容存在哪？ | 只落在应用沙箱（`filesDir` / `DSH_HOME`）；诊断报告导出时**显式剔除凭据与消息内容**（`Index.exportDiagnostics` 的注释与实现） |
| 凭据怎么存？ | 凭据写入走中枢（Host 侧），客户端不落明文；`CredentialSheet` 的明文只在一次请求内存在 |
| 剪贴板 | 只**写**（复制消息/诊断报告）；读剪贴板已按 E370 删除 |

### 3b. 应用内也能看到（P7-11）—— 且与包内声明**逐项对账**

AppGallery 的材料分两半：**控制台里填的**与**应用里能看到的**。后者已经在应用里了：
**设置 → 设备 → 隐私与权限说明**（折叠块，默认收起）——

- **数据做法 6 条**：不收集个人信息 / 数据只在本机沙箱 / 网络只连两处（本机回环 Host、你显式填写的远端）/
  不读设备标识 / 剪贴板只写不读 / 导出内容剔除敏感项。每条都写"能核实的做法"，不写"我们很重视隐私"这类话；
- **申请的权限 2 项**：逐条给用途（`INTERNET`、`KEEP_BACKGROUND_RUNNING`）；
- **版本与日期**：`v1.0（2026-09-15）` —— AGC 里那份文本以此为基准，改一侧就要同步另一侧。

两半之间最容易出的问题不是"没写"，而是**漂移**（文档说两项权限，包里悄悄多一项）。
所以有**第 10 道门禁** `tools/check-compliance.mjs`，做三件事：

1. **逐项对账**：`module.json5` 的 `requestPermissions` 与 `model/PrivacyDisclosure.PERMISSION_DISCLOSURES`
   必须完全一致（多一项、少一项都红）；
2. **禁用清单**：12 项**刻意不申请**的权限（读剪贴板 / 位置 / 相机 / 麦克风 / 通讯录 / 日历 / 媒体 / 健康 /
   Wi-Fi / 跨设备同步…）一旦出现在包里即红 —— 要加就得先改这张表，也就是**改产品原则的一次有意识决定**；
3. **界面出口存在**：设置页确实渲染了这两段（否则"应用里能看到"是空话）。

**归真验证**：临时往 `module.json5` 塞 `ohos.permission.READ_PASTEBOARD` ⇒ 门禁当场两条红（"说明里没有它" +
"申请了刻意不申请的权限"）；还原 ⇒ 绿。

> AGC 侧仍需填写：**隐私政策文本**与"个人信息收集清单"（本应用可如实写"不收集个人信息"），以及数据安全声明。这些在控制台完成，代码侧没有对应字段；应用内那份是它的摘要。

## 5. 体积（已知取舍，登记备查）

release HAP（本机实测）：**270 MB / 74 个文件**。构成：

| 项 | 大小 | 说明 |
|---|---|---|
| `libs/arm64-v8a/libnode.so.127` | 115 MB | 内嵌 Node 运行时（jitless） |
| `dsh-core-0.1.5-rc.2-*.zip` | 67 MB | 内置核心**旧版** |
| `dsh-core-0.1.5-rc.3-*.zip` | 67 MB | 内置核心**当前版** |
| 其余（libvips/rsvg/glib/koffi 等原生件 + `modules.abc` + 资源） | ~21 MB | |

**两个核心版本是刻意的**：端侧没有下载通道，"切回上一版"必须**本机就有那一版**（`BundledCore.installBundledCores` 逐个落地 resfile 里的容器）。
⇒ 若后续要压体积，正确的做法是**先确认"保留上一版"这个能力要不要**（要就得占这份体积；不要就去掉旧版并同步删掉回滚入口），
而不是"顺手删一个 zip"。x86_64 只占 1.3 MB（模拟器用），不值得为它做 ABI 分流。

## 6. 发布构建与签名

### 6.0 出包方式：一条命令（`tools/build-release.mjs`）

```bash
node tools/build-release.mjs            # 前置检查 → 构建 → 报告（约 1–2 分钟）
node tools/build-release.mjs --check    # 只做前置检查（秒级）
```

它做三件事，把"上架要能重复产出发布包"这条要求变成可执行的东西：

1. **先体检签名材料**：读 `build-profile.json5` 的 signingConfigs，逐个检查 `.p12` / `.cer` / `.p7b`
   在不在本机 —— 不在就**先**说清"会产出未签名包 + 上架前还差什么"，而不是让人等两分钟才看到
   `Invalid storeFile value`；
2. 用**正确的一套环境变量**（CLT / `DEVECO_SDK_HOME` / `JAVA_HOME`）跑
   `hvigorw assembleHap -p buildMode=release`；
3. **报告产物**：签名状态、体积 Top 条目、以及**可疑内容**（sourcemap / 测试包 / 源码）。

**本机实跑读数**（2026-09-15）：

```
签名材料：三个文件都不在本机（都在开发机的 C:\Users\hnzy1\.ohos\config\ 下）
构建    ：编译与打包全过，停在 SignHap（00303107 Invalid storeFile value）
产物    ：entry/build/default/outputs/default/entry-default-unsigned.hap
          体积 269.7 MB
          Top：libnode.so.127 109.4 MB / dsh-core-rc.2 66.0 MB / dsh-core-rc.3 66.0 MB
               / librsvg-2.so 5.1 MB / libvips.so 2.6 MB
可疑内容：**无**（无 sourcemap、无测试包、无 .ts/.ets 源码）
```

⇒ 也就是说：**除了签名材料，发布包这条链路已经通了**；而上架包里**没有不该发出去的东西**（这一条以前没人查过）。

### 6.1 本轮修通：release 打包链路

**修前**：`hvigorw assembleHap -p buildMode=release` **直接失败**：

```
ERROR: 00304036 Not Found
The obfuscation rule file './obfuscation-rules.txt' cannot be found in …/platform/obfuscation-rules.txt
The error module is platform
```

根因：`platform` 与 `hostruntime` 两个模块的 `build-profile.json5` 里声明了 `ruleOptions.files: ["./obfuscation-rules.txt"]`，
**但这两个模块没有该文件**（`entry` / `appstate` / `connection` / `dshcompat` 有）。debug 构建不读这一项，所以此前一直没人发现——
**只有 release 会红**，也就是说"上架包"此前根本打不出来。

**修后**：六个模块都有了 `obfuscation-rules.txt`，release 一路跑到 `SignHap`，产出
`entry/build/default/outputs/default/entry-default-unsigned.hap`。
顺带把六个文件的内容统一成"**混淆保持关闭**"并写清理由与开启前提（原来那几份里写着 `-enable-property-obfuscation` 等指令，与 `enable: false` 自相矛盾——
一旦有人把开关打开，协议层按字符串读字段（`getString(value,'sessionId')`）会**静默失效**）。

### 6.2 仍然缺的：release 签名

`build-profile.json5` 里的 `signingConfigs` 是 **DevEco 调试证书**（`keyAlias: "debugKey"`），
且三个文件（`.p12` / `.cer` / `.p7b`）都在开发机的 `C:\Users\hnzy1\.ohos\config\` 下 ⇒ 本机（Linux 容器）与 CI 都无法签名。

上架需要（**必须在 AGC + DevEco 完成**）：

1. 在 AGC 创建应用，生成**发布证书**（`.cer`）与**发布 Profile**（`.p7b`），下载 `.p12`（密钥库）；
2. 在 DevEco 的 `Project Structure → Signing Configs` 里新建一个 **release** 配置指向它们（不要把调试证书用于上架包）；
3. 建议**不要把签名配置提交进仓库**：当前 `build-profile.json5` 里的口令字段虽经 DevEco 加密（换机器即失效），
   但发布密钥库一旦入库就是事故。可行做法见 §7。

### 6.3 混淆

**当前关闭**（`enable: false`），理由写在每个 `obfuscation-rules.txt` 里：协议层按**字符串字段名**读上游 JSON、大量对象要交给内嵌的 Node 运行时；
开属性混淆前必须用 `-keep-property-name` 列出全部 wire 字段名，并用 `tools/check-core-loop.mjs`（本机对真 Host 的核心闭环）回归。
上架**不要求**混淆，但若开启，按上述顺序做。

### 6.4 提交步骤（照抄即可，P7-12）

> 目标是"拿到签名材料后，不必再回头查文档就能提交"。每一步都写清**在哪做**、**填什么**、
> **怎么确认做对了**。仓库侧能自动判定的部分已做成门禁（§9 的第 1 条，现在同时管权限与包元数据）。

**第 0 步：仓库侧自检（本机，1 分钟）**

```bash
node tools/check-compliance.mjs      # 权限对账 + 包元数据/资源引用预检（必须绿）
node tools/build-release.mjs --check # 签名材料体检（现在应报"缺三个文件"）
node tools/check-arkts-entry.mjs     # ArkTS 编译（必须 0 error）
```

**第 1 步：在 AGC 建应用（控制台）**

| 字段 | 填什么 | 备注 |
|---|---|---|
| 应用名称 | `HDSH`（与 `AppScope` 的 `app_name` 一致） | 改名要同步改资源，否则包内名与商店名不一致 |
| 包名 | `com.hnmrxz.hdsh` | **上架后不可改**，必须与 `AppScope/app.json5` 逐字一致 |
| 应用分类 | 工具 / 效率（按实际选） | — |
| 支持设备 | 手机、平板、PC/2in1 | 与 `module.json5.deviceTypes` 一致（门禁会核对这三项都在） |
| 版本号 / 版本名称 | `1000000` / `1.0.0` | **每次提交 versionCode 必须递增**（当前值来自 `app.json5`） |
| 隐私政策 | 见 §3b：应用内「设置 → 设备 → 隐私与权限说明」的文本就是政策正文 | AGC 需要可访问的 URL 或文本；文本以 `PrivacyDisclosure.ets` 为**单一真值** |
| 权限说明 | 两项：`INTERNET`（连你指定的 Host）、`KEEP_BACKGROUND_RUNNING`（长任务后台继续） | 与 §2 表格逐字一致（门禁强制一致） |

**第 2 步：生成发布签名材料（AGC + DevEco）**

1. AGC → 证书管理 → 新建**发布证书**（`.cer`）→ 按提示生成 `.p12`（**密钥库口令另存**）；
2. AGC → Profile 管理 → 新建**发布 Profile**（`.p7b`），绑定上面的证书与包名；
3. DevEco → `Project Structure → Signing Configs` → 新建 release 配置，指向这三个文件；
4. **不要把发布材料提交进仓库**（理由与替代做法见 §6.2 / §7）。

**第 3 步：出包（本机，1–2 分钟）**

```bash
node tools/build-release.mjs       # 先体检 → 构建 → 报告签名状态与可疑内容
```

**确认做对了**：
- 报告里 `签名状态` 是 **已签名**（不是 `SignHap` 失败）；
- 产物是 `entry/build/default/outputs/default/entry-default-signed.hap`；
- `可疑内容：无`（无 sourcemap / 测试包 / 源码）。

**第 4 步：在 AGC 提交**

| 材料 | 来源 |
|---|---|
| 已签名 HAP | 第 3 步产物（**不要**用 `-unsigned.hap`） |
| 应用图标（商店展示用，216×216 PNG） | 需另备（包内分层图标是 1024×1024，见门禁输出） |
| 应用截图 | 需另备：手机 / 平板 / PC 三形态各 3–5 张（覆盖会话、工具卡、设置、图片消息） |
| 应用描述 / 更新说明 | 需另写（一页内说清"本机优先、不动你的数据"） |
| 测试账号 / 复现说明 | **必须**：本应用需要用户自己的 Host 地址与令牌 ⇒ 审核说明里要写清"如何得到一个可连的 Host"（或提供演示 Host 与令牌） |

**第 5 步：真机验收留证（可与提审并行）**

`docs/device-validation.md` 的 **D1–D31** 是"我们声称可用"的证据；**上架前至少要把 D1–D5 与 D29–D31 做掉**（安装启动、连接、发消息、看图、发图、图片解码器状态）。

## 7. 建议的仓库卫生改进（未擅自改动，登记待决策）

`build-profile.json5` 的 `signingConfigs` 目前把 `certpath` / `profile` / `storeFile` / **口令**都写进了受版本控制的文件。
影响：① 路径是开发机专属（换机即无效）；② 发布密钥若照此办理就会入库。
建议二选一：**①** 保持文件只放调试配置，发布签名在 DevEco 里另建（并在提交前确认口令字段被替换为占位）；**②** 把 `signingConfigs` 移到本地不追踪文件（DevEco 支持多份 build-profile 片段）。**本项不擅自改**：改了会直接影响使用者本机的调试安装。
