# 开发计划

> 执行入口：给开发代理/AI 使用。每阶段都以“代码可验证”为优先，不等待真机才能推进。

## P8｜稳定性与技术债收口

**目标**：让当前已完成的功能变成可发布的稳定底座。

任务：
1. 清理文档/代码口径冲突，SDK 固定 `6.1.1(24)`。
2. 解决 API 24 编译器警告与运行时兼容项；对每个系统 API 设最低版本证据或回退。
3. 检查 `runtime/`、原生库、Node 头文件、核心包等容易被 `.gitignore` 误伤的构建输入。
4. 保持纯模型、协议、fixture、门禁可以无设备执行。
5. 建立 Host 启停、断线、重连、后台/前台、异常退出的状态机验收。

**出口**：新克隆可重复构建；纯逻辑门禁全绿；API 24 不再有已知功能性警告。

## P9｜四形态 UI 收口

**目标**：同一产品模型，四种稳定表达：手机、折叠屏、平板、2in1。

任务：
1. `Breakpoints → LayoutController → NavigationController` 继续保持唯一决策链。
2. 手机：单栏、底部操作、键盘避让、长列表性能、单手热区。
3. 折叠：闭合单栏；展开双栏/主从；折叠状态改变时保留任务上下文。
4. 平板：导航栏 + 内容栏；详情按空间让步；不把桌面三栏硬塞进窄宽度。
5. 2in1：窗口尺寸变化、键鼠、右键/悬停/快捷键、拖拽、窗口记忆、多窗口共享状态。
6. 所有 Sheet、Dialog、Toast、通知统一系统表达。

**出口**：同一功能在四形态均有明确入口，无重复状态机，无“点击无反应”入口。

## P10｜运行时治理

任务：核心版本仓库、校验、激活事务、回滚、插件部署、升级迁移、备份恢复、损坏检测。

原则：`staging → validate → activate → observe → rollback`；任何失败保留旧可运行版本。

## P11｜性能与可靠性

建立可重复指标：冷启动到可交互、首次会话、长会话事件数、消息列表帧率、内存峰值、后台恢复、网络抖动、连续运行、频繁窗口创建/销毁。

性能优化顺序：先减少重复状态计算与无效渲染，再优化图片/文本，再优化 Host/IO；不得为了指标破坏可诊断性。

## P12｜发布与持续升级

任务：签名、AGC 预检、发布说明、版本兼容矩阵、升级/降级测试、隐私说明、崩溃回收、回归清单。

## 优先级纪律

P0 阻塞核心闭环；P1 影响日常使用；P1.5 影响跨形态体验；P2 影响治理/发布；P3 装饰与低频增强。除非前一层明确关闭，否则不得用 P2/P3 工作掩盖 P0/P1 缺口。
