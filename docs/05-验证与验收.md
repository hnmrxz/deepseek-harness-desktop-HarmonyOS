# 验证与验收

## 1. 验证分层

| 层级 | 环境 | 目标 |
|---|---|---|
| L0 | 本机 Node | 纯模型、协议投影、fixture、布局、错误映射 |
| L1 | 本机 DevEco CLI | ArkTS/CMake 编译、静态检查、打包预检 |
| L2 | HarmonyOS x86_64 模拟器 | UI 结构、窗口、输入、系统能力大部分回归 |
| L3 | HarmonyOS arm64 真机 | 性能、系统 API、通知、权限、后台、功耗、触控、折叠 |
| L4 | 发布包 | 签名、安装/升级/回滚、AGC 提审资源 |

远程开发没有模拟器/真机时，只做 L0/L1；不得为了“看起来完成”修改代码绕过 L2/L3。

## 2. 每个功能的验收

1. 纯规则有 fixture。
2. 协议接线有最小闭环。
3. 主路径有成功与失败用例。
4. UI 入口无假按钮。
5. 多形态至少有布局决策测试。
6. 设备专属行为进入设备清单。

## 3. 核心回归集

- Host 启动/停止/异常退出。
- 首次连接、自动重连、token 不可用。
- 会话创建、切换、恢复。
- 首次发送成功、发送失败恢复草稿、已排队不重复发送。
- 长连接断开、重试倒计时、恢复后继续。
- 工具、命令、审批、目标、子代理、任务、交付物。
- `@`/`/` 输入触发与 token 替换。
- 多窗口共享连接，关闭窗口不影响其他窗口。
- 插件与核心版本切换/回滚。

## 4. 设备验收最小矩阵

### 手机

竖屏、横屏、软键盘、深浅色、后台恢复、通知点击回到会话、长列表滚动。

### 折叠屏

闭合/展开/半折、旋转、双栏切换、窗口恢复、连续会话不丢上下文。

### 平板

横向主布局、导航与详情让步、附件/文件选择、分屏/多窗口。

### 2in1

窗口缩放、鼠标 hover、右键、键盘快捷键、拖拽、多窗口、窗口几何记忆。

## 5. 发布门槛

- `devecocli` 编译与静态检查通过。
- 仓库既有 10 道门禁全部通过。
- 核心闭环 fixture 全绿。
- 发布包资源/权限/设备类型预检通过。
- 签名包可安装并完成首次使用。
- 升级前后数据可读；失败可回滚。

## 6. 远程开发策略

开发代理默认先实现 L0/L1；需要 L2/L3 时，只新增“待设备验证”的测试条目，不阻塞其它模块。所有无法验证的系统行为必须写出假设、风险与设备测试方法。
