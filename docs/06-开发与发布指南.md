# 开发与发布指南

## 环境

需要 DevEco Command Line Tools、JDK 17、Node.js。Node.js 仅用于仓库脚本；端侧运行使用随包 Node Runtime。

## 常用流程

```bash
devecocli build
node tools/pack-core.mjs --skip-install --place-in-app
node tools/place-host-app.mjs
```

先运行仓库已有的门禁/检查脚本，再安装到模拟器或真机。签名材料不进 Git。

## 资源闭包

新克隆确认以下输入存在：

- `entry/src/main/cpp/node-headers/`
- `entry/libs/<abi>/`
- `entry/src/main/resources/resfile/*.zip`
- `entry/src/main/resources/resfile/resources/app/`

缺失时先修依赖闭包，不要在业务代码里添加临时 fallback 掩盖构建问题。

## 提交规范

一次提交尽量只包含一个明确工作流：例如“协议事实收口”“UI 原生化”“错误恢复”“构建修复”。避免代码、文档、无关格式化同时混入。

提交说明应包含：问题、事实依据、改动边界、验证结果、未验证项。

## 上游升级

升级 dsh 时依次执行：

1. 记录上游 commit / 版本。
2. 更新协议事实与错误码。
3. 搜索新增 `undici` / WASM / 原生模块依赖。
4. 运行核心闭环 fixture。
5. 运行 UI 接线门禁。
6. 检查 API 版本与构建依赖。
7. 在设备上验证 Host、网络、通知、文件、后台。

禁止直接覆盖当前稳定核心；新核心必须 staging → validate → activate。

## 发布

发布前完成：版本号递增、设备类型核对、权限核对、图标/label/入口资源核对、release 构建、签名、安装验证、升级验证、AGC 提审材料准备。

审核说明必须能让审核人员理解如何进入一个可用的 Host/会话状态，避免“安装成功但没有可操作内容”。
