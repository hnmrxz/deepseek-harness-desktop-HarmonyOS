# 上游升级手册（DSH Upstream Upgrade Runbook）
> 本文档于 2026-09-19 精简；完整版见 git 历史。

## 1. 架构前提（评审逐条检查，违反任一即为架构回归）

上游知识只允许出现在 `dshcompat`（HAR）：`Endpoints.ets`（自动生成，勿手改）/ `Surface.ets` / `Aliases.ets` / `CompatIndex.ets`。
判定标准：① `connection/src` 与 `entry/src` 中 grep 不到任何具体 endpoint 名与字段名；② `appstate/src` 中 grep 不到上游字段名字面量（`raw` 透传除外）；③ 新增上游依赖时只改 `dshcompat`。

## 2. 升级流程（五步）

```sh
node tools/compat-drift.mjs                                               # 步骤0：确认当前状态（已报漂移=基线未同步，先处理存量）
node tools/protocol-contract.mjs --json .research/protocol/contracts.json # 步骤1：提取新上游契约
node tools/compat-drift.mjs                                               # 步骤2：漂移门禁；退出码0=无漂移跳步骤4，1=有漂移（报告按新增/移除/契约变化给出差异与处置清单）
node tools/gen-compat-endpoints.mjs                                       # 步骤3：重新生成上表
# 已知陷阱：流式标记在 Remote({mode:"stream"}) 装饰器、不在 descriptor；声明包要从 id（<declPkg>#<ns>/<method>）里取
```

步骤3 改动落点（均在 `dshcompat`）：`Endpoints.ets` 由生成器改写（能力映射改生成器 `CAPABILITIES` 后重跑）；`Aliases.ets` 上游字段改名时更新 `FIELD_ALIASES`（别名顺序=优先匹配顺序）；`CompatIndex.ets` 的 `SUPPORTED_VERSIONS` 加入新版本、骨架端点变化同步 `PROTOCOL_SKELETON`；`Surface.ets` 在载体路径/事件流端点/开流 payload 变化时改。

## 3. 升级风险清单（差异类型 → 端侧行为）

| 差异类型 | 影响 | 要求 |
|---|---|---|
| 新增端点 | 无（默认不调用） | 可选：接入新能力走正常需求流程 |
| 移除端点 | 能力不可用（调用 HTTP 404） | 必须降级：入口置灰 + 说明（`evaluateCapability` 的 `missing`） |
| 参数形状变化 | 调用失败 | 更新上表；禁止在调用点写兼容分支 |
| 流式标记变化 | 载体用错被拒（`gateway/signature-invalid`） | 更新上表；`buildArgs` 之外不得自行判断载体 |
| 状态码/错误码语义变化 | 错误呈现与重试策略受影响 | 更新 `CompatIndex` 判定与 D2 §8.4 错误码表 |
| 骨架端点缺失 | 不兼容 | `checkVersion` 给 `INCOMPATIBLE`，拒绝连接并说明 |

降级策略（能力降级而非崩溃）：必需端点缺失→入口置灰 + tooltip 说明（不隐藏入口）；可选端点缺失→功能局部降级、不提示错误（如缺 `session/fork` 则隐藏分支入口）；尚未探测（unknown）→按可用处理、首次调用失败后再置灰；骨架缺失→拒绝连接并提示「Host 版本过旧或不是 dsh Web 表层」。实现落点：`dshcompat` 的 `evaluateCapability()` 返回 `CapabilityState`（present / missing / unknown）。

版本矩阵（唯一声明处：`CompatIndex.ets` 的 `SUPPORTED_VERSIONS`）：`SUPPORTED`=版本在清单内；`UNVERIFIED`=不在清单但骨架端点齐全→可用 + 常驻「Host 版本未经验证」提示；`INCOMPATIBLE`=骨架端点（`session/list`、`session/create`、`session/prompt`）缺失→拒绝连接并给升级建议。版本号只读核心包 `@deepseek-ai/dsh` 的版本，不读外层打包包版本。

## 4. 升级后必须重跑的门禁/校验命令

```sh
node tools/compat-drift.mjs                              # 静态：漂移必须为 0
dsh web --no-open --port 3111 --host 127.0.0.1           # 起 Host（输出 token 用于下一步）
node tools/protocol-probe.mjs --base http://127.0.0.1:3111 --token <token>   # 动态：对真实 Host 跑只读探测矩阵
devecocli build
devecocli build --modules entry@ohosTest
devecocli run                                            # 设备侧：跑生效验证（POC-1 页面）
```
门禁负测试（每次修改门禁后必做；CI 也必跑——未被负测试验证过的门禁等于没有门禁）：备份 `Endpoints.ets` → 手工改错一处 shape/stream 标记 → 期望退出码 1 且精确列出该端点差异 → 恢复 → 期望退出码 0。CI 附加检查：
```sh
DSH_CONTRACTS=.research/protocol/contracts-0.1.2-rc.1.json node tools/compat-drift.mjs && { echo "门禁失效：对旧基线竟然报无漂移"; exit 1; } || echo "负测试通过（如期报出差异）"
grep -rnE "session/|settings/|workspace/|pluginInventory/" connection/src appstate/src entry/src/main/ets/view  # 期望无输出（防上游知识泄漏出 dshcompat）
grep -rn "sys.symbol" --include=*.ets connection/src appstate/src | grep -v dshcompat                       # 期望无输出
node --test hostkit/test/                                # PC 侧搭桥服务（独立测试）
```
跨版本工具：`DSH_CONTRACTS=<旧契约>.json DSH_VERSION=<旧版本> node tools/compat-drift.mjs`（版本间比对）；同变量配 `gen-compat-endpoints.mjs`（跨版本生成）。契约文件带自描述元数据（`out.json.meta.json`），下游工具优先读它判定版本，不靠「当前装了哪个 dsh」猜。
