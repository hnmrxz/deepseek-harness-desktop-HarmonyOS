# 产品与功能说明

## 1. 产品定位

HDSH 是 DeepSeek Harness 的 HarmonyOS 原生客户端与端侧运行载体。核心目标是让用户在 HarmonyOS 手机、折叠屏、平板、2in1 上连续完成“连接 → 选择工作区 → 发起任务 → 观察 Agent → 处理审批/提问 → 查看交付物 → 继续迭代”。

产品不以“复刻网页像素”为目标，而以“保留上游语义、采用 HarmonyOS 原生交互”为目标。

## 2. 用户任务

| 用户任务 | 结果 |
|---|---|
| 开始工作 | 选择或恢复工作区，查看最近会话 |
| 提问/执行 | Composer 支持文本、附件、`@` 引用、`/` 命令 |
| 观察执行 | 在对话与轨迹之间查看回答、工具、命令、子代理、目标、任务、错误 |
| 做安全决策 | 审批卡只暴露真实存在的上游动作；缺少关键事实时 fail-closed |
| 处理中断 | 重试、暂停/恢复目标、修改/清除目标、管理待发队列 |
| 管理环境 | Provider、模型、凭据、插件、核心版本、连接与主题 |
| 跨形态使用 | 手机单栏；折叠/平板双栏；2in1 多窗、键鼠、拖拽、快捷键 |

## 3. 功能范围

### P0：核心闭环

会话创建/恢复、消息发送与失败恢复、流式回答、会话轨迹、工作区关联、本地 Host 生命周期、网络断线恢复、待发队列、审批与提问。

### P1：生产力

附件、文件引用、斜杠命令、工具结果、命令结果、子代理、任务、目标、交付物、搜索与文件浏览、通知、窗口记忆。

### P1.5：HarmonyOS 体验层

系统 Sheet、系统符号、语义颜色/排版/间距、统一 NativePrimitives、断点与布局控制器、输入模态策略、无障碍与触控热区。

### P2：运行时治理

多核心版本并存、校验后激活、失败回滚、插件部署状态、升级迁移、备份恢复、诊断与日志导出。

### P3：发布能力

签名、AGC 预检、升级路径、发布包可重复构建、崩溃/异常观测与隐私说明。

## 4. 明确非目标

- 不把 WebView 作为主 UI。
- 不 fork DeepSeek Harness 的 agent 业务逻辑。
- 不修改上游安全围栏来扩大网络暴露面。
- 不为当前端侧无法可靠支持的能力制造“看起来可点但实际上无效”的按钮。
- 不把 PC 桌面布局缩小后直接用于手机。
- 不把“未在真机验证”写成“已完成”。

## 5. 功能完成定义

一个功能只有同时满足以下条件才可标记 DONE：

`Protocol` 协议入口明确；`State` 状态归属唯一；`Functional` 主路径可完成；`Interaction` 点击/手势有真实结果；`Responsive` 目标形态可用；`Accessibility` 可访问；`Validation` 有可重复验证方法；`Failure` 有失败与降级路径。

## 6. 体验优先级

优先保证：发送与恢复 > Agent 执行反馈 > 审批/提问 > 工作区与文件 > 会话管理 > 高级配置 > 装饰性视觉。

任何视觉优化不得以削弱上述核心闭环为代价。
