## 一、一句话结论

真机验收把 **32 条缺陷**抓了出来，其中 **8 条是"功能在设备上根本不能用"**（F1/F2/F7/F12/F19/F22/F24/F25）。
已经修掉并**在真机上复验过** 6 条（F1/F7/F9/F19/F22/F29），剩下的是**一条主线 + 三块专题**：

| 主线 | 内容 |
|---|---|
| **M1 人机回路** | 审批与提问**整条走不通**（F7 已修一半 → 还差 F12/F18 的可达性 + F21 的重启丢失 + F28 的反馈链） |
| **M2 命令与面板** | 命令在手机上**没有可达的执行入口**（F24 只修了"敲完按发送"这一条路） |
| **M3 图片链路** | `sharp` 不可用 ⇒ 发图必然失败（F25），且排障出口自己没接线（F26/F27） |
| **M4 UI 对标官方** | 信息密度与官方还差一档（过程分组、回合 ± 行数、目标栏不可达、筛选行缺失） |

## 三·0 UI 口径（2026-09-17 明确）：**PC / 平板 / 2in1 与官方 1:1，手机端适应性优化**

> 最新口径（第 26 轮）：**PC、平板、2in1 完全 1:1 复刻官方 UI**（在能完整实现的功能范围内）；
> **手机端做适应性优化，但图标与整体风格保持一致**。
> 落地方式：`Index` 在档位变化时把 `LayoutMode` 发布到 `AppStorage('dshLayoutMode')`，
> 需要分档的组件用 `@StorageProp` 读——**一处真值，不新增第二条判定链**。
