### §2.2 F2 的另一半：子代理会话**可以打开**（第 60 轮取证，**不是** B 类）

> 之前把它归成"B 类边缘（需要父级地址通路，本仓没有）"。**这一轮把通路找出来了，而且本仓早就写好了。**

**核心的契约**（`@deepseek-ai/dsh-api-session-controller/lib/types/types.d.ts`）：

```ts
export type SessionAddress =
  | { kind: 'session';  sessionId: SessionId }
  | { kind: 'subagent'; parentSessionId: SessionId; childSessionId: SessionId;
      mode: 'one-shot' | 'continuable' };
```

**为什么普通地址会被拒**（同包 `history.js` 的 `validateAddress`）：

```js
if (address.kind === 'session') {
  if (header.origin === 'subagent') {
    throw new RemoteError('session/agent-busy',
      'subagent Sessions require their durable parent address',
      { reason: 'use subagent delivery for this child session' });
  }
}
```

⇒ 真机上那条报错**说的就是解法**：换成 `kind: 'subagent'` 的那种地址。

**本仓已有的东西**（`model/Wire.ets`）：`FollowSubagentAddress` 接口与
`followSubagentAddress(parentSessionId, childSessionId, mode)` 构造函数**都已经写好了**——
但**没有任何调用点**：`SessionHub.ets:2425` 在 `ensureFollowStream` 里手工拼的是
`{kind:'session', sessionId}`。

**还缺的一块**：地址里的 `mode`（`'one-shot' | 'continuable'`）。本仓目前**没有投影它**
（全仓只有 `Wire.ets` 的注释提到这两个取值）⇒ 实现时要从会话的 `subagent` 投影里读
（`SessionWireHeader.projections.values.subagent` —— `history.js` 里
`const identity = projections?.values.subagent` 用的就是它）。

**下一步的实现清单**（有契约在手，不需要再猜）：
1. ~~投影 `subagent` 描述符，取出 `mode`~~ ⇒ **已完成**（第 61 轮）：新增 `subagentModeOf(raw)`
   （`Wire.ets`）读 `projections.values.subagent.mode`，`SessionListItem` 补 `subagentMode` 字段；
2. ~~`ensureFollowStream` 按 `isSubagentSession` 选地址~~ ⇒ **已完成**（第 61 轮）：
   新增 `followAddressFor(sessionId)`，证据齐备时走 `followSubagentAddress(parent, child, mode)`，
   **用已有的构造函数**（不再手拼 `{kind:'session'}`）；
3. ~~`session/page` 同源改造~~ ⇒ **已完成**（第 62 轮）：`SessionAddressWire` 从**单形态接口**改成**联合**（`FollowSessionAddress | FollowSubagentAddress`）——此前子代理地址在**类型上就表达不出来**，调用方只能手工拼普通地址；`sessionPagePayload()` 改为接收地址，两个端点**共用 `followAddressFor()` 一处判定**。

**判定口径（写清楚，免得被"顺手放宽"）**：只在 **`isSubagentSession` 为真 + `parentSessionId` 非空
+ `subagentMode` 非空**三条都成立时才走子代理地址；缺任何一条就**退回普通地址**。
理由：那个地址里 `mode` 是必填，**编一个默认值会让一条 `continuable` 的会话以 `one-shot` 的语义被打开**
——**错的语义比打不开更糟**（用户会把"续跑不生效"归到别的原因上）。

> **顺带记一条门禁的边界**：`followSubagentAddress` / `followSessionAddress` 是
> **导出但零调用**的，而 `check-dead-code` **没报**——因为 barrel 里的 `export {…}` 被算作"消费者"。
> 也就是说：**"导出了但没人用"这类死代码，门禁只看得见一层**。
> 这一条是靠人读代码发现的，记在这里，免得以后误以为门禁覆盖了它。

**这一节的结论（写进方案，避免以后做错）**：

**第 31 轮又核实一条同类**：**F21（待决跨重启丢失）也是 B 类**。判据同样硬：
`clientId` 由 `$events` 的 `ready` 帧按**流代次**下发（不是客户端选的），重连后必变、

⇒ waterfall 投递给上一代事件流之后就取不回来了。**"重连后重拉一次待决"这个修法根本不存在**——
方案里原先写的就是它，现已纠正为"只能如实说明"。

| 5 | **同一机理要串起来记** | `height('100%')` 在"高度不定的父容器"里失效，**三次**踩到（F12/F18/F20）；双层包装**两次**（F7/F28）；"同一件事两套口径"**两次**（F15/F23）。串起来之后，第四次能在动手前认出来 |
| 6 | **读数本身也会骗人** | `dumpLayout` 报的是**节点属性**不是视觉结果（"展开"折叠过也照样报全文）；`hilog -x` 读后清缓冲；我自己的两次结论（"目标正文为空"、"F32 行不存在"）都是**打印/时点**造成的假读数 |
