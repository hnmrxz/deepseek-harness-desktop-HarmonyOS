# HarmonyOS 多端 UI 设计规范

## 1. 设计目标

“Web 语义一致、HarmonyOS 表达原生、多形态不是缩放版”。

用户在不同设备上看到的是同一产品模型，但导航、布局、输入方式和浮层形态根据窗口与交互能力变化。

## 2. 视觉层级

`Tokens.ets` 定义尺度档位；`HarmonyTheme.ets` 定义语义角色；`NativePrimitives.ets` 提供可复用原生组件。页面禁止直接大量写颜色、字号、圆角与描边裸值。

当前 SDK 为 `6.1.1(24)`，因此不假定 API 26 的新材质能力。未来升级 SDK 后，先更新 Theme 能力层，再逐页迁移。

## 3. 四形态

| 形态 | 默认布局 | 关键交互 |
|---|---|---|
| 手机 | 单栏 | 底部主要操作、滑动、长按、键盘避让 |
| 折叠闭合 | 单栏 | 保持手机任务连续性 |
| 折叠展开 | 双栏/主从 | 导航与内容并列，状态不重建 |
| 平板 | 导航 + 内容 + 条件详情 | 更宽列表、更少弹层 |
| 2in1 | 多栏/多窗 | 鼠标、键盘、右键、悬停、拖拽、快捷键 |

实际布局由 `Breakpoints.ets`、`LayoutController.ets`、`NavigationController.ets` 决策；不得在页面里重复判断宽度。

## 4. 交互规则

### Sheet

半模态优先使用系统 `bindSheet`，全应用采用单浮层宿主。遮罩、拖拽关闭、键盘避让交给系统。

### 按钮

任何按钮必须满足：有真实 action；action 有成功/失败反馈；无条件不可用时明确禁用或隐藏。禁止“看起来可点但没有 onClick”的入口。

### 状态

加载、运行、等待、失败、完成必须可区分；网络等待不能伪装成静态空白。

### 输入

`@`/`/` 触发结果应替换当前 token，而不是简单追加；长按/右键/悬停等差异通过 `InputPolicy` + `InputFacts` 收敛。

## 5. 对话与轨迹

对话承担“我要做什么、发生了什么”；轨迹承担“Agent 内部执行了什么”。工具/命令/重试/审批/目标等不应冒充普通助手回答。

长会话优先保证增量更新与滚动稳定；自动贴底遵循 `Follow` 模型，用户主动上滑后不得强行抢回视口。

## 6. 无障碍

交互热区、语义标签、颜色对比、动态字体、键盘焦点顺序必须与视觉设计同时验收，不在发布前临时补。

## 7. 视觉验收

每个主要页面至少验证：手机竖屏、折叠展开、平板横屏、2in1 窗口缩放；窄宽度下不得出现内容截断、横向溢出、浮层遮挡关键操作。
