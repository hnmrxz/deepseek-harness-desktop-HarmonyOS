# UI / 返回交互审计

> 本文档于 2026-09-19 精简（保留被代码/门禁引用的锚点结论）；完整版见 git 历史。

完成定义：UI 只有同时满足"功能存在 + 状态正确 + 返回正确 + 多形态正确 + 可见区域完整 + 无障碍基本可用 + 无假入口 + 有失败反馈"才可标记 DONE。静态审计确认的结构风险在无真机时只登记为风险，不宣称已复现。

## P0：返回/关闭语义

1. 要求：文件预览的返回优先级按"预览此刻是否**整页层**"（`previewIsLayer()`）判定——整页层排在"下钻"之前，并排栏排在页面层级之后；关预览同时把下钻退回文件树（`drillAfterPreviewClosed()`）；组合态 fixture 为全组合矩阵 2304 种（已处理 P8-1；多栏下预览作右栏面板是否吃返回键见 D40）。
2. 要求：所有"退回一层"的入口（系统返回键、各页头返回箭头）统一到 `Index.consumeBack()` 一个执行点；浮层复位只保留 `closeSheet()` 一处；关文件预览走中枢 `closeFilePreview()`——视图只清本地镜像 = 假关闭（已处理 P8-1）。**仍缺**：关闭原因（完成/取消/返回/系统关闭/外部状态变化）未回传调用方，登记在 `docs/07`。
3. 要求：根层 `EXIT` 交给系统而不是 push 首页；所有需留在应用内的返回动作必须被消费。

## P0：页面覆盖、裁切与可见区域

4. 要求："100% 高度"不是"安全区域完整可见"的充分条件——页面根、滚动内容、固定操作栏、Composer、底部导航和 Sheet 内容必须明确属于"可用内容区"，不得靠 `100%` 让子节点碰运气。
5. 要求：固定高度/宽度组件必须有最小可用宽度与让步顺序；固定高度不能承载不可预测长度文本（窄屏、折叠闭合、分屏、大字号场景）。

### 6. 文本省略不能代替信息可达（锚点：被 MessageRow.ets、check-feature-wiring.mjs 引用）

- 要求：标题可以省略，但必须能够进入详情查看完整文本；
- 要求：错误、路径、模型名称等关键诊断信息不能仅靠一行省略；
- 要求：只有纯装饰性/次要摘要允许强制单行；必须区分"视觉截断"和"用户无法获取完整信息"。

### 7. 操作区被内容挤压时不得静默消失

（锚点：被 Composer.ets、ConversationHeader.ets、TimelineOverview.ets、check-feature-wiring.mjs 引用）

- 要求：操作区优先级高于描述文本；窄屏时优先缩短次级文本、折叠操作或进入菜单，而不是让按钮被裁掉。
- 已处理（P8-4b）：三处（输入区工具行、会话头视图切换行、时间总览统计行）从"一行 `Row` + `Blank()`"改成**可换行的 Flex + 两个组**（与官方 composer 的 `flex-wrap: wrap; justify-content: space-between` 同构）——放不下就换行，一个控件都不裁；接线门禁新增「必含模式」规则钉住（改回不换行会当场红）。
- 仍缺：文件行、设置行、命令行未逐个复核（大多已有 `layoutWeight(1)` 弹性元素、优先级正确），真机按 D46 一起看。

8. 要求：Sheet 必须测试"短内容 / 长内容 / 键盘 / 大字号 / 横屏 / 小窗口"六种情况，并确保首尾操作都能滚动到可见。
9. 要求：双栏/三栏 `sidebar + main + detail + resizer` 总宽在窄窗口下不得超过可用宽度，超出时按 `LayoutController` 让步链收缩而非裁切；面板必须有关闭入口；主体保最小可视宽度。

## P1：页面层级与导航（要求清单）

- 页签/二级页/详情 Sheet/文件预览/工作区下钻必须有明确层级，不允许"视觉像页面、行为像浮层"的混合态。
- 同一内容不可同时存在两个可见入口却由不同状态源控制。
- 进入详情后返回应回到原上下文，不重建列表、不清空选择。
- 手机用底部导航/抽屉；大屏不强制复用手机的跳转方式。
- 页签切换不得丢弃未提交的编辑内容；若必须清除，须有明确的提交/取消语义。

## P1：视觉粗糙项（要求清单）

- 首页/工作区：突出"当前工作区 → 当前会话"；空态给原因、下一步动作和返回路径；列表项标题/状态/次级信息/操作区节奏稳定。
- 会话页：Header/消息流/轨迹/目标/输入区形成纵向层次；消息类型靠结构层级区分而非仅背景色；长内容有固定视觉槽位；输入区是"任务终点"（发送/停止/排队/失败恢复/附件/引用不散落多处）。
- 设置页：按"连接 → 模型 → 凭据 → 核心/插件 → 外观/行为 → 高级/诊断"组织；危险操作分组并明确二次确认；只读信息与可编辑字段视觉区分。

## P1：状态与反馈（要求清单）

- 每个异步操作覆盖 idle / loading / success / empty / disabled / error / retrying。
- 禁止：点击后静默等待；错误只写日志不反馈；成功后无状态变化；"按钮样式"的 Text；排队后保留发送入口导致重复操作；失败恢复覆盖用户刚编辑的内容。

## P1：Sheet / Dialog（要求清单）

- `bindSheet` 只用于真正的半模态任务；导航层不得伪装成 Sheet；同一时刻只允许一个真正的浮层宿主，由状态派生当前浮层类型。
- 编辑态关闭前有未保存修改时必须有明确的取消/保存策略。已处理（P8-4）：用户主动关闭时明确说出"已放弃未保存的修改"（没改过不吭声；判定在零依赖 `model/Sheets.sheetDiscardNotice()`，接线见 `Index.dismissSheetByUser()`；不做"关闭前弹确认"）。仍缺：关闭原因未回传调用方、系统级关闭无单独语义。

## P1.5：四形态（要求清单）

- 手机：单手热区、底部操作、键盘避让、返回优先级、长列表贴底优先于大屏功能密度；检查状态栏/手势区/软键盘/底部导航/Composer 互相覆盖。
- 折叠：闭合→展开不重置导航；展开→闭合让步到单栏、恢复后保留选择与滚动上下文；半折检查中缝遮挡。
- 平板：减少 Sheet、多用并排详情；主列表稳定宽度；分屏后重算可用宽度。
- 2in1：窗口缩放/hover/右键/快捷键/拖拽/触控共同工作；同一操作不因输入设备不同而结果不同；宽拖窄时必须"隐藏/让步"而非"裁切"。

## P2：视觉系统与文案（要求清单）

- 字号/圆角/间距/描边/颜色全走 `Tokens/HarmonyTheme/NativePrimitives`；层级 = 页面背景 → 内容面 → 卡片/行 → Sheet → 系统弹窗；图标语义统一；主/次/危险/取消操作有稳定层级；动效只表达状态变化，不掩盖加载或状态不明。
- 错误文案回答三件事：发生了什么、是否已生效、下一步能做什么；内部错误码只作诊断信息。
- P3 完成度：发布前逐页清理占位文字、无效操作、空白区域、重复标题、过度圆角、无意义卡片、过长说明、隐藏状态、不可解释的图标。

## 覆盖/裁切专项矩阵

| 场景 | 必须验证 | 失败判据 |
|---|---|---|
| 手机竖屏 | 状态栏、Header、Composer、底部导航 | 任一固定操作被系统区域或其它组件盖住 |
| 手机软键盘 | Composer、Sheet、输入触发层 | 键盘遮住输入框/发送键/候选项 |
| 折叠闭合 | 主体与系统手势区 | 文本/按钮落入不可交互区域 |
| 折叠半折 | 中缝两侧内容 | 关键文字或操作跨中缝 |
| 平板分屏 | nav/main/detail 总宽度 | 任一列被裁切或操作区消失 |
| 2in1 缩窗 | 轨道让步链 | 宽度不足时靠裁切而非降级 |
| 动态字体 | 标题、按钮、设置项 | 文本盖住按钮或按钮被挤出 |
| 长路径/错误 | 完整信息可达 | 只剩省略号且无详情入口 |
| 长 Sheet | 首尾动作可达 | 最后一个按钮无法滚动到可见 |
