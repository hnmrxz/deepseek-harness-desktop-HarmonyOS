# 12 · 设置页契约（`settings/describe` 实测）

> 状态：**已实测**（2026-09-11，对 0.1.5-rc.1 真实 Host 只读探测）。
> 采集脚本：`node .research/protocol/probe-settings.mjs --base <url> --token <token>`。
> 本文件是「真实数据接设置页」这一步的输入基线。**动手前先读本文**，
> 否则必然要去猜 schema 的序列化格式（猜错的后果是设置页显示一堆无名空白项，且不报错）。

## 1. 回复顶层

```jsonc
{
  "writable": true,        // Host 是否接受写；false 时**所有**写控件都必须禁用
  "hasDocument": true,     // 是否有本地设置文档（不暴露 Host 路径）
  "namespaces": [ /* 每个已注册命名空间一项 */ ]
}
```

实测规模：`namespaces = 14` 个，`writable = true`，`hasDocument = true`。

## 2. 命名空间视图

```jsonc
{
  "ns": "ui-theme",
  "schema": { /* schemastery toJSON，见 §3 */ },
  "value": { /* 已脱敏的**解析后**值：schema 默认 → 组合基线 → 用户层 */ },
  "base":  { /* 可选：组合基线层 */ },
  "user":  { /* 可选：用户层原文；**字段出现在这里 = 被用户覆盖** */ },
  "applies": "live",       // 'live' | 'restart'
  "secrets": [ { "path": ["apiKey"], "set": false } ],
  "revision": 0            // 写回时必须带上（expectedRevision），否则并发写会互相覆盖
}
```

**关键事实（都由实测确认）**：

1. `value` 是**三层合并后的结果**，不是用户层。想表达「此项已被用户覆盖」必须看
   `user` 里有没有该字段——只看 `value` 无法区分「默认值」与「用户显式设成同一个值」。
2. `secrets[].path` 是**数组**，`ref = path.join('.')` 且**不带命名空间前缀**
   （与 D2 §8.7.2 第 18 条一致）。`set` 表示该槽位当前是否有值，**值本身永不上线**。
3. `revision` 是**写操作的并发令牌**，不是展示字段。上游对过期写返回
   `settings/conflict{ns, expected, actual}`，客户端必须重新读取后再写。
4. `applies: 'restart'` 的命名空间，改动后需要重启 Host 才生效——界面必须如实提示，
   不能让用户以为已经生效。实测 14 个命名空间**全部是 `live`**。

## 3. `schema` 的序列化格式（schemastery `toJSON()`）

**这是必须看实测才能写对的部分。** schema 不是一个嵌套树，而是一张
**以 `uid` 为键的扁平表** + 一个根 uid：

```jsonc
{
  "uid": 231,
  "refs": {
    "220": { "type": "const", "meta": {"required": true}, "value": "light" },
    "225": { "type": "union", "meta": {"default": "system"}, "list": [220, 222, 224] },
    "230": { "type": "number", "meta": {"step": 1, "min": 12, "max": 17, "default": 14} },
    "231": { "type": "object", "meta": {"default": {}}, "dict": {"preference": 225, "fontSize": 230} }
  }
}
```

要点：

- **`dict`**：对象字段名 → 子节点 uid。**设置项就来自这里**，且它通常只在根上有；
  嵌套对象（如 `llm-deepseek` 的 `retryPolicy`、`models[]` 的元素）也是 `dict`。
- **`union`**：`list` 是候选 uid；枚举选择项在实测里普遍是
  `union(list: const…, const…)`。**枚举的显示名在 `const.value` 里**（就是取值本身），
  上游没有单独的 label 字段。
- **`array`**：`inner` 是元素 uid。列表型设置（`models[]`）需要「编辑列表」，
  第一版可只读展示。
- **`meta`** 是字段级约束的**唯一**来源：`required`、`default`、`min`/`max`/`step`
  （数字）、`pattern`（字符串，形如 `{source, flags}`）、`role`。
  实测 `role: 'credential-ref'` 出现在 `llm-deepseek.apiKeyEnv` 上——
  这正是「这个设置项其实是一个凭据引用」的机器可读标记，设置页应把它渲染成凭据选择/链接，
  而不是一个普通文本框。
- **`const`**：常量字段（枚举分支）。根级 `dict` 里一般不会直接出现，只在 `union.list` 里。

## 4. 实测的 14 个命名空间与字段（摘要）

| ns | 字段 | 类型 | 备注 |
|---|---|---|---|
| `agent-default-model` | `provider` / `model` / `reasoningEffort` | string ×2 + string | 默认路由 |
| `subagent-model-selection` | `enabled` / `allowedModels[]` | boolean + array\<object\> | |
| `ui-theme` | `preference` / `fontSize` | union(light/dark/system) + number(12–17) | |
| `locale` | `preference` | string(pattern) | 实测 `value = {}`（未设） |
| `ui-onboarding` | `welcomeNoticeVersion` | string | 实测 `value = {}` |
| `ui-conversation` | `busyEnter` | union(queue/steer) | |
| `ui-chat` | `transcriptView` | union(normal/compact) | |
| `llm-deepseek` | 约 20 项，含 `apiKeyEnv`(role=credential-ref)、`models[]`、`retryPolicy`(union) 等 | | 最大的一项；`models[]` 巨型默认值 |
| `web-search-deepseek` | （含 1 个 secret 槽位） | | 唯一有 `secrets` 的命名空间之一 |
| …其余 4 个 | 见探测输出 | | |

> 实测的 `locale.value = {}` 与 `ui-onboarding.value = {}` 说明
> **「未设」是常态**：设置页必须能把「继承默认」与「用户显式设值」分开显示，
> 否则用户会以为这些项「已经配好了」。

### 5.2 待做（**下一步**）

1. **写路径（最重要）**：`settings/set` 带 `expectedRevision`；冲突
   （`settings/conflict{expected,actual}`）必须提示「已被其他客户端改动，已重新读取」
   而不是静默失败。
   **当前状态：设置页控件是启用的但只读**——点击会给出「未实现写回」的显式说明。
   之所以不禁用：读值是真的，整页禁用会让用户以为连读取也坏了；
   之所以不静默：静默的假成功是最坏的失败形态（用户下次打开才发现值没变）。
2. **数组 / 嵌套对象编辑器**：实测的 `llm-deepseek.models[]`（4 个模型、每个约 8 个字段）
   与 `retryPolicy`（union）。需要先实测「写一个数组元素」的线上效果再动手。
3. **`null` / union 多分支**：实测 `union` 有「对象分支」形态（`llm-deepseek.retryPolicy`
   是 `union(object, object)`），当前按只读展示——需要实测写哪个分支。
4. **凭据写路径**：`credentials/set` / `credentials/unset`（`set` 返回 **void**，
   不要把 void 回复当失败，见 D2 §8.7.6 缺陷 2 的同类陷阱）。
5. **`settings/set` 的 `applies: 'restart'` 提示与 `document-updated` 事件刷新**。

## 6. 纪律

- 本文件里的字段名、结构、取值**全部来自实测**；新增条目必须附采集脚本与日期。
- 上表 14 个命名空间是**该 Host 的当前部署**，不是上游常量：
  不同 Host 装的插件不同，命名空间集合就不同。代码里**不得**硬编码命名空间清单
  （那是又一张「前缀猜测表」）。
